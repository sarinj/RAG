# Shared service contract — v1 draft

This is the authoritative cross-service contract for the three [implementation plans](../implementation/README.md). If an older planning document differs, this contract takes precedence. No service agent may change it independently. It is a proposed local, single-user, non-streaming MVP contract; authentication, supported languages, hardware, and model configuration still require user decisions before production implementation.

## Ownership and change control

- Backend owns public API, TypeORM migrations, upload storage, conversations, and document lifecycle.
- LLM backend owns internal chat API, model calls, chunk creation, and leased ingestion execution. It uses the schema below; no Python migrations.
- Frontend consumes the public API only. It never calls Python, Ollama, or the database.
- Lead owns this document and integration decisions. Request changes with the proposed field/schema, reason, and affected consumers. Update all plans, OpenAPI schemas, fixtures, and consumers together.
- Implement `info.version: 1.0.0` in both OpenAPI documents. Backend exports `backend/openapi.json`; Python exports `llm-backend/openapi.json`. Frontend generates `src/generated/api.ts` from the former; backend generates `src/modules/llm-client/generated.ts` from the latter. Generated files are not edited manually.
- This Markdown contract controls intent; generated OpenAPI controls implemented wire types. A mismatch blocks integration. CI will regenerate and check for uncommitted schema/type drift and validate shared examples against both producer and consumer schemas.

## Common wire conventions

- JSON uses camelCase; SQL uses snake_case. IDs are UUID strings; timestamps are UTC RFC3339 strings. Required nullable fields are emitted as `null`, not omitted.
- Unknown request properties are rejected. Responses may gain optional fields without consumers failing.
- All HTTP errors use `{ "code": "ERROR_CODE", "message": "Safe human message", "requestId": "uuid" }`. Never expose prompts, SQL, stack traces, or storage paths.
- `X-Request-Id` correlates logs and responses; backend generates it if absent. Chat body `requestId` is a separate persistent idempotency key.
- List requests accept `limit` (default 20, maximum 100) and optional opaque `cursor`. Responses are `{items: T[], nextCursor: string|null}`. Stable ordering uses `createdAt,id`: documents/conversations descending; messages ascending.
- Public routes start `/api`; internal chat is `/internal/chat`. No streaming in v1.

## Public DTO definitions

The following TypeScript-like notation specifies JSON shape, not a shared runtime package.

```ts
type Scope = { mode: 'all' } | { mode: 'selected'; documentIds: string[] };
type Failure = { code: string; message: string };
type Job = {
  id: string;
  status: 'queued' | 'processing' | 'succeeded' | 'failed' | 'cancelled';
  stage: 'queued' | 'parsing' | 'chunking' | 'contextualizing' | 'embedding' | 'publishing' | 'done';
  processedChunks: number;
  totalChunks: number | null;
  error: Failure | null;
};
type Document = {
  id: string; name: string; mimeType: string; sizeBytes: number;
  status: 'queued' | 'processing' | 'ready' | 'failed' | 'deleted';
  activeGenerationId: string | null;
  latestJob: Job | null;
  createdAt: string; updatedAt: string;
};
type Conversation = {
  id: string; title: string; scope: Scope; createdAt: string; updatedAt: string;
};
type Citation = {
  label: string; // S1, S2, ... unique within one answer
  documentId: string; generationId: string; chunkId: string;
  documentName: string;
  pageStart: number | null; pageEnd: number | null; heading: string | null;
};
type Message = {
  id: string; conversationId: string; requestId: string;
  role: 'user' | 'assistant';
  status: 'pending' | 'completed' | 'failed';
  content: string; // pending/failed assistant has empty content
  answerStatus: 'answered' | 'insufficient_evidence' | null;
  citations: Citation[];
  error: Failure | null; createdAt: string; updatedAt: string;
};
type Turn = { requestId: string; userMessage: Message; assistantMessage: Message };
type Source = Omit<Citation, 'label'> & { text: string }; // original text only
```

Pages are 1-based inclusive; TXT/Markdown have null page fields. A cross-page chunk uses start/end pages. Heading is nullable. Citations appear in answer text as `[S1]`; UI uses labels to associate source metadata. Insufficient-evidence answers have no citations. Nonempty answers marked `answered` require at least one valid citation.

Document status describes availability. During reindexing a document stays `ready` with its old active generation; latestJob reflects processing or failure. First ingestion follows queued → processing → ready/failed. Deletion is terminal. UI must not infer searchability solely from latestJob.

## Public endpoints

| Method/path | Input | Success | Notes |
| --- | --- | --- | --- |
| POST `/api/documents` | multipart, exactly one `file` | 202 `Document` | job included in latestJob; no frontend-controlled storage key |
| GET `/api/documents` | pagination | 200 page of Document | excludes deleted rows |
| GET `/api/documents/:id` | none | 200 Document | deleted tombstone may be returned; unknown ID 404 |
| POST `/api/documents/:id/retry` | `{}` | 202 Document | queued/processing job returns current state; otherwise only failed latest job may retry |
| POST `/api/documents/:id/reindex` | `{}` | 202 Document | ready only; uses current server indexing config; existing active job returns current state |
| DELETE `/api/documents/:id` | none | 204, empty body | commits tombstone/cancellation before success; physical cleanup retried in background; repeat delete 204 |
| GET `/api/documents/:id/chunks/:chunkId` | none | 200 Source | backend derives generation; deleted source 410; unknown/unrelated chunk 404 |
| POST `/api/conversations` | `{title?: string, scope: Scope}` | 201 Conversation | default title `New chat`; title 1–120 trimmed characters |
| GET `/api/conversations` | pagination | 200 page of Conversation | includes empty conversations |
| GET `/api/conversations/:id` | none | 200 Conversation | scope immutable in v1; change selection by creating another conversation |
| GET `/api/conversations/:id/messages` | pagination | 200 page of Message | includes pending/failed assistants |
| POST `/api/conversations/:id/messages` | `{requestId: string, content: string}` | 200 Turn; 202 Turn if same request is still pending | content 1–8000 trimmed characters |

Public errors: 400 `VALIDATION_ERROR`; 404 `NOT_FOUND`; 409 `DUPLICATE_DOCUMENT`, `INVALID_STATE`, `NO_READY_DOCUMENTS`, `DOCUMENT_NOT_READY`, `REQUEST_ID_CONFLICT`, `TURN_IN_PROGRESS`, `SCOPE_CHANGED`, or `INDEX_CONFIG_MISMATCH`; 410 `SOURCE_DELETED`; 413 `FILE_TOO_LARGE`/`CORPUS_LIMIT_EXCEEDED`; 415 `UNSUPPORTED_FILE_TYPE`; 422 `EMPTY_DOCUMENT`/`CONTEXT_LIMIT_EXCEEDED`/`INVALID_CITATIONS`; 503 `MODEL_UNAVAILABLE`; 504 `GENERATION_TIMEOUT`. Validation during worker processing records a Failure in latestJob instead of returning a delayed HTTP error to upload.

Duplicate upload by active content hash returns 409; UI can refresh the list. The same bytes can be uploaded again after the earlier document is deleted. Duplicate handling is transaction-safe.

## Scope and chat lifecycle

- Selected scope has 1–100 unique IDs. Every selected document must be ready at conversation creation and at each turn; do not silently drop missing/unready/deleted selections. `all` resolves to all ready, non-deleted documents at the beginning of each turn. Zero ready documents returns `NO_READY_DOCUMENTS` before creating messages.
- Resolve and save a snapshot of `(documentId,generationId)` for the turn. Both retrieval methods must use exactly that snapshot and exclude deleted documents. New uploads do not join an in-flight turn.
- Permit one pending turn per conversation. Reject a different concurrent request with `TURN_IN_PROGRESS` before inserting messages.
- Atomically insert a completed user message and pending assistant plus turn record. Repeating the same request ID/content in that conversation returns the stored result; changed content returns `REQUEST_ID_CONFLICT`. A pending duplicate gets 202 and polls message history. A failed duplicate returns its stored failed Turn (200); an intentional new attempt uses a new request ID.
- NestJS calls Python synchronously outside the database transaction. On success, lock scoped documents in stable ID order, recheck not deleted and same active generations, then persist completion. If anything changed, discard the answer and persist `SCOPE_CHANGED` failure. Deletion/publication uses compatible row locks. A deletion after successful completion may invalidate later source lookup, which returns 410.
- On provider errors persist a failed assistant before returning the mapped HTTP error. The frontend reloads history to discover saved failure state. A recovery sweep marks expired pending turns failed after API restart; only the original pending, unexpired turn may complete.
- Initial timeout ordering: Python generation deadline 120 s; NestJS internal timeout 130 s; browser timeout 150 s; turn expiry 180 s. These are configuration defaults to benchmark, not latency promises. A transport timeout is ambiguous: inspect the existing request, never automatically issue a new ID.
- Python is stateless for chat persistence. History contains only completed user/assistant exchanges, excludes the current question, and is bounded to the last 10 pairs by NestJS; Python additionally enforces token budgets. Previous assistant text is not evidence.

## Internal chat contract

Require `Authorization: Bearer <INTERNAL_API_TOKEN>` and propagate `X-Request-Id`. Internal network only; never expose the token in the browser.

```ts
type ChatRequest = {
  contractVersion: '1.0.0';
  requestId: string; // turn idempotency key
  question: string;
  history: { role: 'user' | 'assistant'; content: string }[];
  sources: { documentId: string; generationId: string }[]; // nonempty
  retrievalMode: 'vector' | 'hybrid';
};
type ChatResponse = {
  contractVersion: '1.0.0'; requestId: string;
  answer: string;
  answerStatus: 'answered' | 'insufficient_evidence';
  citations: Citation[];
};
```

`POST /internal/chat` returns 200 ChatResponse or the same error envelope. Python validates request version (400 `CONTRACT_VERSION_MISMATCH`), token (401 `UNAUTHORIZED`), and source generations against the DB (409 `SCOPE_CHANGED`). NestJS validates response version, requestId, citation scope, and chunk membership before persistence. Citation labels must be unique, resolve to retrieved original chunks, and match markers in answer text. Do not expose prompts, retrieval debug output, or generated contextual descriptions as sources.

Retrieval mode is server-controlled from the shared index configuration (`retrievalMode: 'vector' | 'hybrid'`) and passed through the internal chat contract. The default is hybrid. Indexing mode is separate: `baseline` or `contextual`, captured on each generation. Query embeddings must match every scoped generation's embedding configuration; mixed spaces fail `INDEX_CONFIG_MISMATCH` until reindexing is complete.

## Shared database schema

TypeORM owns migrations. These names and types are binding; extra internal columns require a coordinated contract update if Python reads/writes the table. Text states use CHECK constraints. Times use `timestamptz`, IDs `uuid`, counts `integer`, byte sizes `bigint`. Foreign keys are restrictive unless a deletion policy below says otherwise.

| Table | Required columns |
| --- | --- |
| documents | id PK, name text, mime_type text, size_bytes bigint, content_hash text, storage_key text, status text, active_generation_id uuid nullable, created_at, updated_at, deleted_at nullable, cleanup_completed_at nullable |
| index_generations | id PK, document_id FK, mode text (`baseline/contextual`), status text (`queued/processing/ready/failed/cancelled`), embedding_model text, embedding_digest text, embedding_dimension integer, config jsonb, created_at, updated_at |
| ingestion_jobs | id PK, document_id FK, generation_id FK UNIQUE, status text (Job status), stage text (Job stage), processed_chunks integer default 0, total_chunks integer nullable, attempts integer default 0, lease_token uuid nullable, lease_expires_at nullable, heartbeat_at nullable, error_code text nullable, error_message text nullable, created_at, updated_at |
| chunks | id PK, generation_id FK, ordinal integer, original_text text, context_text text nullable, searchable_text text, page_start integer nullable, page_end integer nullable, heading text nullable, source_start integer, source_end integer, token_count integer, embedding vector(D), created_at |
| conversations | id PK, title text, scope_mode text (`all/selected`), created_at, updated_at |
| conversation_documents | conversation_id FK, document_id FK; composite PK |
| chat_turns | id PK, conversation_id FK, request_id uuid, question text, sources jsonb, status text (`pending/completed/failed`), expires_at, created_at, updated_at |
| messages | id PK, turn_id FK, conversation_id FK, role text (`user/assistant`), status text (`pending/completed/failed`), content text, answer_status text nullable, error_code text nullable, error_message text nullable, created_at, updated_at |
| message_citations | message_id FK, label text, document_id FK, generation_id uuid, chunk_id uuid, document_name text, page_start integer nullable, page_end integer nullable, heading text nullable; PK (message_id,label) |

`D` is intentionally unresolved until the model probe; no agent guesses it. Generation `config` has required keys: `chunkTargetTokens`, `chunkOverlapTokens`, `chunkerVersion`, `tokenizerVersion`, `contextPromptVersion` (nullable for baseline), `contextModel` (nullable), `contextModelDigest` (nullable), `contextWindowTokens`, `maxOutputTokens`. These are immutable once the job starts. Source offsets are zero-based, half-open Unicode code-point offsets into the parser's normalized full document text, not original file byte offsets.

Indexes/constraints: unique `(generation_id,ordinal)` on chunks; unique `(conversation_id,request_id)` on turns; unique `(turn_id,role)` on messages; partial unique conversation pending turn; partial unique document active job (`queued/processing`); partial unique active content hash (`deleted_at IS NULL`); indexes on job status/lease expiry, chunk generation, conversation message order. Active generation must belong to its document (composite FK or equivalent enforced invariant). Conversation scopes retain document tombstones. Add the active-generation FK after creating generation tables.

No FK from citation generation/chunk IDs: they remain provenance identifiers after physical deletion. The document FK points to a retained tombstone. Old successful generations/chunks remain readable for historical citations until document deletion, but only the active generation is retrievable. Cap total stored chunks, including retained generations; reject reindexing if capacity cannot accommodate staging. Later retention/garbage collection requires a separate design.

### Job protocol and writers

1. Backend creates document, generation, and queued job atomically after storing file bytes. Retry creates a new generation/job copying the failed configuration; reindex uses current configuration. No mutation of finished job records to recycle them.
2. Worker claims queued or expired processing work with `FOR UPDATE SKIP LOCKED`, increments attempts, assigns a new lease_token, and commits quickly. Initial lease 90 s, heartbeat every 20 s, maximum 3 automatic attempts. At exhausted attempts mark failed; explicit user retry creates a fresh job.
3. All worker writes verify the current lease token, unexpired lease, and non-deleted document under transaction locks. Expired workers cannot write chunks or publish. Retrying a generation clears its staged chunks under the new lease before starting over.
4. Worker stages chunks and reports progress. It must not hold a DB transaction across parsing/model calls. Publication locks document then job, verifies token/cancellation and complete chunks, marks generation ready/job succeeded/stage done, and swaps active_generation_id atomically. The old ready generation remains intact.
5. A failed initial job makes document failed. A failed reindex leaves document ready with the old active generation. Job failure exposes a sanitized error; its last stage stays visible.
6. Backend deletion locks document then active job, writes deleted status/date, nulls active_generation_id, and cancels job/generation. A backend cleanup sweep removes bytes and chunks/generations, then marks cleanup_completed_at. Remove referencing finished ingestion jobs before generations. Retries are safe after partial cleanup. Tombstones/conversation links/citation IDs remain.
7. Deleting documents does not erase previously generated chat text, which may quote them. Source bodies are no longer available; explain this retention behavior in UI/docs. A future “erase all derived content” feature requires a new contract.

Lock order when multiple rows are needed: documents sorted by UUID, then jobs, then turn/message state. Claim transactions lock jobs only and commit before acquiring document locks. Lease/publication transactions and deletion must not invert this order.

### Capacity coordination

The 5,000-chunk provisional cap includes all stored chunks, including staged and historical generations. Every transaction inserting chunks takes `pg_advisory_xact_lock(71001)` after its document/job locks, counts existing rows, and rejects a batch that would exceed the cap with `CORPUS_LIMIT_EXCEEDED`. All chunk writers use that same lock; deleting rows only reduces usage. This deliberately simple rule fits a small local corpus. File-count admission is serialized in backend upload transactions using a separate advisory key `71002`. Reindex capacity failure leaves the previous generation ready. These constants are contract values, not independently selected per service.

### Configuration and deployment interface

Service ports: web 3000, NestJS 3001, Python 8000, PostgreSQL 5432, Ollama 11434. Compose DNS names: `frontend`, `backend`, `llm-backend`, `llm-worker`, `postgres`, `ollama`. Worker/API share one Python image. Bind only browser/public API ports to localhost by default.

| Variable | Consumers | Meaning |
| --- | --- | --- |
| NEXT_PUBLIC_API_BASE_URL | frontend | browser-reachable base ending `/api` |
| DATABASE_URL | backend, Python | service-specific DB credentials in deployment |
| INTERNAL_API_TOKEN | backend, Python | identical secret for internal HTTP |
| LLM_BASE_URL | backend | `http://llm-backend:8000` in Compose |
| LLM_PROVIDER | Python | `ollama`, `openai`, `claude`, `gemini`, or `huggingface`; selects the generation adapter |
| LLM_PROVIDER_BASE_URL, LLM_PROVIDER_API_KEY | Python | optional generation endpoint and provider credential |
| EMBEDDING_PROVIDER | Python | `ollama`, `openai`, `gemini`, or `huggingface`; defaults to `LLM_PROVIDER` except Claude defaults to Ollama |
| EMBEDDING_PROVIDER_BASE_URL, EMBEDDING_PROVIDER_API_KEY | Python | optional independent embedding endpoint and credential; same-provider credentials/URL are reused by default |
| OLLAMA_BASE_URL | Python | `http://ollama:11434` or agreed host URL |
| UPLOAD_DIR | backend, worker | `/data/uploads`, shared storage key mapping; worker read-only |
| GENERATION_MODEL, EMBEDDING_MODEL | Python/bootstrap | selected runtime models |
| EMBEDDING_MODEL_DIGEST | Python | pinned embedding fingerprint for hosted embedding providers; must match index config |
| INDEX_CONFIG_PATH | backend, Python | same mounted, validated JSON indexing configuration including retrieval mode, embedding dimension/digest, and generation config keys |
| INDEX_MODE | backend | `baseline` initially, `contextual` after rollout |
| retrievalMode | shared index config | `hybrid` by default; use `vector` for a deliberate baseline comparison |

Model bootstrap writes a reviewed configuration artifact consumed by both services. Do not derive different configurations from each service's independent defaults. Secrets are excluded from that artifact. Migrations use the agreed dimension literal and startup verifies it against the artifact.

Both HTTP services provide `GET /health/live` → 200 `{status:'ok'}` and `GET /health/ready` → 200 `{status:'ready'}` or 503 error envelope. Python readiness checks DB/config/model availability; backend checks schema/storage/internal service readiness. Worker health is its heartbeat and process state. Root integration scripts and Compose are lead-owned.

## Required integration fixtures

Before consumer implementation, the lead and producer create versioned JSON fixtures under `docs/contracts/fixtures/v1/` for queued, ready, failed, reindexing documents; selected/all scope; completed/failed/pending turns; answered/no-evidence internal responses; and deleted source error. These files are a planned gate deliverable, not yet generated schemas or passing tests.

All three service plans must use those same fixtures. At integration, validate them against generated OpenAPI and replace fixture-driven demos with real requests. Contract review must explicitly cover unknown IDs, no ready documents, pending duplicate messages, reindex races, and deletion.
